## Project Overview

Kazemaru is a project management web application with an ASP.NET Core 9 backend and Angular 17 frontend, using PostgreSQL and Redis.

## Commands

### Backend (`/backend`)
```bash
dotnet build                                    # Build solution
dotnet run --project Kazemaru.WebApi            # Run API (dev)
dotnet test                                     # Run tests
dotnet ef migrations add <Name> --project Kazemaru.Infrastructure --startup-project Kazemaru.WebApi
dotnet ef database update --project Kazemaru.Infrastructure --startup-project Kazemaru.WebApi
```

### Frontend (`/frontend`)
```bash
npm start          # Dev server at http://localhost:4200
npm run build      # Production build
npm test           # Unit tests (Karma/Jasmine)
```

### Infrastructure
```bash
docker-compose up   # Start PostgreSQL (port 5436) and Redis (port 6379)
docker-compose down
```

## Architecture

Clean Architecture with four backend layers:

- **Kazemaru.Domain** — entities and repository interfaces only; no dependencies on other layers
- **Kazemaru.Infrastructure** — EF Core `KazemaruDbContext`, repository implementations, Npgsql/Redis clients
- **Kazemaru.Application** — services, DTOs, AutoMapper profiles; depends on Domain and Infrastructure interfaces
- **Kazemaru.WebApi** — ASP.NET Core controllers, middleware, DI wiring, Scalar API docs; depends on Application

Controllers map 1:1 to services: `AuthController → AuthService`, `ProjectsController → ProjectService`, etc. `TokenService` handles JWT creation/validation; refresh tokens are stored in Redis and delivered as 30-day cookies.

The Angular frontend uses services (`/services`) for all HTTP calls with an auth interceptor that attaches the JWT. Route guards (`/guards`) protect authenticated pages. Pages live in `/pages`, reusable UI in `/components`.

## Database

PostgreSQL is initialized from `/utils/scripts/kazemarudb.sql`, which creates all tables, default statuses, and triggers for automatic `updated_at` timestamps. **EF Core is used for querying but the schema is managed via the SQL init script, not EF migrations.** All PKs are UUIDs generated by `gen_random_uuid()`.

- Dev connection: `Host=localhost;Port=5436;Database=postgres;Username=postgres;Password=postgres`
- Redis: `localhost:6379` (dev), `redis` (Docker)

## Configuration

App settings are split across `appsettings.json` and `appsettings.Development.json` in `Kazemaru.WebApi`. Key sections: `JwtConfig` (secret, issuer, audience, expiry), `RedisConfig`, `ConnectionStrings`, `FirstUser` (auto-created superuser on first run).

CORS allows any header/method from the configured `ClientOrigin` (default `http://localhost:4200`).
